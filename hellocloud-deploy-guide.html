Argo CD 설치에서 이미지 다운로드 오류 해결까지. 아래 단계를 눌러 오늘 한 일이 다음 작업과 어떻게 이어지는지 확인해요.

한 일

dev에 v3.6.1 설치 · Pod 7개 Ready

Argo CD부터 실행돼야 Git의 배포 설정을 읽고 반영할 수 있어요. READY는 각 Pod가 요청을 처리할 준비가 됐는지 보여줘요.

확인 명령어 · 팀 dev SSH
kubectl get pods -n argocd

다음 할 일
웹 앱을 관리 대상으로 등록합니다.

한 일

웹 dev 태그를 1615df9로 갱신

태그는 GHCR에 보관된 이미지 중 실행할 버전을 고르는 값이에요. Helm은 이 값을 배포 YAML의 image 항목에 넣어요.

확인 명령어 · 로컬 WSL · 팀 저장소
git fetch origin && git grep -n 'tag:' origin/main -- deploy/values/web/values-dev.yaml

다음 할 일
Argo CD가 새 태그를 읽어 Pod 설정에 반영하는지 봅니다.

한 일

web-dev 등록 · 새 태그가 Pod에 반영됨

Application은 Argo CD에 어느 Git 브랜치와 Helm 설정을 읽고 어디에 배포할지 알려줘요. Synced는 Git 설정이 반영됐다는 표시예요.

확인 명령어 · 팀 dev SSH
kubectl get applications.argoproj.io web-dev -n argocd

다음 할 일
Progressing이 계속되면 웹 Pod의 상태를 봅니다.

한 일

Pod Events에서 GHCR 401 확인

노드 배정은 성공했어요. 그다음 노드가 이미지를 받으려 했지만 GHCR이 인증 요청을 거절했어요. 재시도 간격이 늘어나며 ImagePullBackOff가 표시됐어요.

확인 명령어 · 팀 dev SSH
kubectl get pods -n ideaconnection-dev
kubectl describe pod POD_NAME -n ideaconnection-dev

다음 할 일
POD_NAME은 조회 결과의 실제 이름으로 바꿔요. Events에 401이 보이면 이미지 접근 권한부터 확인합니다.

한 일

GHCR 공개 전환 후 Synced / Healthy · 1/1 Running

같은 웹 Pod를 다시 조회해 준비 상태를 확인했어요. 클러스터 안에서 웹이 실행됐으니 이제 팀 공용 주소에서 접근할 수 있는지 볼 차례예요.

확인 명령어 · 팀 dev SSH
kubectl get applications.argoproj.io web-dev -n argocd
kubectl get pods -n ideaconnection-dev

Gateway 연결 후 팀 공용 주소를 열고, dev DB·Keycloak 준비 후 로그인과 조직 API를 확인합니다.

Helm 검사가 실패했던 이유

PR #77에서 실제 태그를 넣으니 기존의 ‘빈 태그면 실패해야 한다’는 검사가 성공으로 끝나 CI가 실패했어요. 그 검사에 --set-string 'image.tag='를 넣어 빈 값을 직접 시험하도록 고쳤어요.

bash deploy/scripts/validate-helm.sh
공용 dev 작업 전 확인

Git과 Helm 검사는 로컬 WSL에서, 클러스터 상태 조회는 dev SSH에서 해요. 앱 등록은 실제 서버를 변경하므로 팀 절차에 따르고 토큰과 비밀번호는 문서나 채팅에 올리지 않아요.
