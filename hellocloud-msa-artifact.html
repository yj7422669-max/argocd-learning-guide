01 · 서비스 지도

HelloCloud에서 누가 무엇을 맡을까?

서비스하는 일어디에 저장하나
user사용자와 조직 소속 확인MySQL에 사용자·조직 정보
chat메시지 보내기와 지난 대화 조회MongoDB에 메시지, Redis로 새 메시지 알림 전달

채팅 예시 · 오늘 보낸 메시지를 내일 다시 읽으려면 MongoDB에 기록이 남아 있어야 해요. 상대 화면에 새 메시지를 바로 표시하는 데는 Redis를 통해 전달한 알림을 써요.

02 · 개발 환경 비교

MySQL·MongoDB·Redis는 어디에 띄울까?

호스트에 직접 설치

각자 PC의 운영체제에 설치해요. Docker가 없어도 실행할 수 있고, 버전·포트·설치 방법은 팀원이 각각 맞춰야 해요.

Docker Compose로 실행

공통 compose.yaml에 버전과 포트를 정해요. 같은 파일로 구성 요소를 띄우고, 저장할 데이터는 볼륨에 보관해요.

예시 · 두 사람이 같은 Compose 파일로 MySQL을 켜도, 한 사람이 만든 테스트 조직은 그 사람의 로컬 DB에만 들어 있어요. 함께 같은 데이터로 확인할 때는 팀 dev를 써요.

03 · 요청을 보내는 주소

chat이 user에게 묻기 전에 맞출 두 가지

API 명세 · 어떻게 물어볼까?

예를 들어 조직 번호와 사용자 번호를 보내고, 멤버인지 답을 받기로 약속해요.

접속 주소 · 어디에 물어볼까?

요청을 받을 user 서비스의 주소와 포트를 설정해요. 로컬과 dev의 주소는 환경에 맞춰 바꿀 수 있어요.

localhost 예시 · chat이 컨테이너 안에서 localhost에 요청하면 그 chat 컨테이너 자신에게 가요. 같은 Compose 네트워크의 다른 컨테이너라면 Compose에 적힌 서비스 이름과 내부 포트로 연결해요.

04 · 다른 팀원의 기능이 필요할 때

서로 다른 곳에서 어떻게 함께 확인할까?

내 PC에서 함께 실행

chat을 개발하면서 user도 내 PC에 띄워 연결해 봐요. 개인 테스트 데이터를 자유롭게 준비할 수 있어요.

팀 공용 dev에서 확인

팀이 정한 경로로 dev에 접속해 배포된 버전을 함께 확인해요. 내 PC의 앱에서 dev 서비스를 호출하려면 그 서비스에 연결할 수 있는 팀 승인 경로가 필요해요.

우리 팀 dev에서는 앱이 Kubernetes에서 실행되고, MySQL은 별도 DB VM에서 실행돼요. 앱에서 DB 주소로 실제 연결되는지 확인해야 해요.

팀원과 풀어 보기

PR을 머지했는데 chat이 user에게 요청하지 못해요. 어디부터 볼까요?

공용 dev에서 두 서비스가 실행 중인지 확인해요. 그다음 chat이 요청하는 user 주소와 포트가 맞는지, 요청 경로와 데이터가 API 명세와 맞는지 살펴봐요. 내 PC의 localhost는 내 PC를, 컨테이너의 localhost는 그 컨테이너 자신을 가리켜요.
